# v0.24.1 — Erma Grounding Reliability

Date: 2026-08-09
Channel: preview hotfix

## Why this patch exists

The first production run of v0.24.0 proved that factual routing was activating correctly, but it also exposed a deployment gap: the application could be deployed with the grounded-search code enabled while no Google/Brave search credential was available to the Cloudflare Worker. In that state `search_web` failed, the planner could retry the same failed search in another round, and the evidence-bound final-answer policy produced an unnecessarily long refusal for ordinary static questions.

## Changes

- Production preflight now requires at least one complete search provider to already exist as a Cloudflare Worker secret before production deploy succeeds.
- Supported readiness paths are Gemini Google Search grounding, Brave Search, or the complete legacy Google Custom Search API key/CX pair.
- Search credentials remain independently managed encrypted Cloudflare secrets and are never passed through `--var` or mutated by the application deployment workflow; `GOOGLE_GROUNDING_MODEL` remains a non-secret server-side variable.
- A terminal `search_web` failure stops further planner web-search rounds for the request, preventing duplicate failed attempts.
- Static low-risk factual questions can fall back to concise model background that is explicitly marked as not externally verified, instead of asking the user to provide their own sources.
- Current, legal, medical, financial, safety-critical, and official-statistical claims remain evidence-bound and do not receive a confident memory-only fallback.
- The existing Kazakhstan entity resolution, multilingual query expansion, source ranking, privacy minimization, and ten-mode Erma personality layer remain intact.

## Production configuration

At least one production search provider credential must be configured as a Cloudflare Worker secret before deploying this hotfix:

- `GOOGLE_GEMINI_API_KEY` or `GEMINI_API_KEY` for the preferred Google grounding path; or
- `BRAVE_SEARCH_API_KEY` for Brave fallback; or
- both `GOOGLE_SEARCH_API_KEY` and `GOOGLE_SEARCH_CX` for the legacy Google Custom Search fallback.

The repository and deployment workflow never store or print the credential values. Secret ownership remains separate from the deployment transaction.

## Verification

The v0.24.1 regression suite covers provider-readiness validation, Cloudflare secret ownership, useful static-fact fallback, and prevention of duplicate failed web-search attempts. Full repository CI must pass before merge.

## Migration

No D1 migration is required.
