# v0.24.2 — Google Direct Grounding

**Date:** 2026-08-09  
**Channel:** Preview / Beta  
**D1 migration:** None

## Summary

v0.24.2 changes the factual web-answer path so eligible factual, current-information, and research prompts can use the official Gemini Interactions API with Google Search grounding as the answer source itself.

Instead of discarding Google's grounded model output and asking NVIDIA to rewrite the retrieved evidence, TK LAB now sends the privacy-minimized current user turn to Google Search grounding and, when Google returns a complete grounded response, displays that response directly in Erma.

This is the official API-backed equivalent of the desired Google-grounded answer flow. It does **not** scrape the consumer `AI Overview` block from google.com, and wording can differ from what the Google Search app shows.

## Changes

- Added a direct Google Search grounding transport using the Gemini Interactions API.
- Eligible standalone `fact_lookup`, `fresh_information`, and `research` routes send only the minimized current user turn to Google; the full conversation history is not sent to the search provider.
- Context-dependent follow-ups such as short pronoun/deictic questions stay on Erma's context-aware pipeline instead of being detached from their conversation and sent as standalone Google prompts.
- A complete Google grounded answer bypasses NVIDIA rewriting and is returned directly for both SSE chat streaming and JSON API responses.
- Direct answer quality uses a separate `GOOGLE_DIRECT_GROUNDING_MODEL` setting, defaulting to `gemini-3.6-flash`; the lower-cost `GOOGLE_GROUNDING_MODEL` remains available for retrieval and compatibility fallback.
- Compatibility fallback from the preferred direct model is limited to model-level 400/404 failures. HTTP 429 is not retried against another Google model, preventing one user turn from multiplying exhausted provider quota.
- Direct pass-through requires evidence that Google actually executed web search plus URL citations and Search Suggestions. Incomplete grounding falls back to the existing Erma verification pipeline.
- Google Search Suggestions are rendered in a sandboxed attribution surface and returned citations are exposed as source links.
- Added `google-grounding` response provenance so product telemetry can distinguish direct Google-grounded answers from NVIDIA and local fallbacks.
- Local archive sanitation now preserves bounded Google grounding metadata, citations, Search Suggestions, and the `search_web` tool trace so attribution survives reloads.
- Kazakhstan exact-fact routes now use an explicit no-guess fallback policy: if external verification is unavailable, Erma must not reconstruct zhuz/clan/tribe membership, rankings, current officeholders, legal facts, dates, or exact lists from model memory.
- The provider-health snapshot now exposes an optional `google_grounding` model/key accessibility check. This is a readiness signal, not proof that a particular Search-grounded request has remaining quota.
- Direct pass-through remains behind TK LAB safety policy. Blocked, restricted, and high-impact prompts continue through the normal safety/synthesis path.
- Existing Kazakhstan entity handling, source ranking, privacy-minimized search, Google Custom Search fallback, and Brave fallback remain available.

## Synthetic validation

Before finalizing the patch, the current production v0.24.1 API was exercised through the same SSE endpoint used by the chat UI. The baseline exposed two important failure modes: production web retrieval was returning tool errors for current Kazakhstan queries, and the older fallback could then produce incorrect Kazakhstan taxonomy from model memory. The test also confirmed that the public guest quota stops repeated automated probing after the allowed daily generations, so the production baseline was deliberately bounded.

The patch now includes deterministic synthetic coverage across current Kazakhstan news, Senior Zhuz membership, Kazakhstan demographics/history/current officials, Kazakh-language prompts, English factual prompts, casual chat, math, code, analysis, comparisons, and planning. The direct-Google tests also cover exact prompt forwarding, Search attribution, JSON/SSE parity, provider-model compatibility fallback, 429 behavior, and the Kazakhstan no-guess fallback.

A true live semantic check of the new direct Google path still requires the v0.24.2 Worker configuration to be deployed (or canaried) because production currently runs the older release. No production traffic is changed by this PR itself.

## Privacy and provider behavior

The direct Google route sends the privacy-minimized current turn, not the complete chat history. It is still external-provider processing: under Google's current Grounding with Google Search terms, prompts, contextual information, and generated output used for grounded results and Search Suggestions are stored for 30 days, and that storage cannot be disabled for this feature.

The TK LAB Product Facts, Privacy Policy, and Subprocessors disclosure have therefore been updated. The legal bundle version is `2026-08-09` with a new content digest so the consent surface can distinguish the changed processing terms.

## Reliability behavior

Google quota and rate limits still apply. If direct Grounding with Google Search returns HTTP 429 or another transient provider error, TK LAB cannot bypass the exhausted Google quota; it falls back to the existing web path when another configured route is available.

The direct path intentionally fails closed to the older verification route when the Google response is missing citations or Search Suggestions rather than presenting an unattributed Google-generated answer as grounded. Kazakhstan exact facts add a stricter final guard: an unavailable search provider is no longer permission to confidently invent a local taxonomy or exact factual list.

## Configuration

A production Cloudflare Worker must already have one of these encrypted secrets:

- `GOOGLE_GEMINI_API_KEY`
- `GEMINI_API_KEY`

Runtime model variables are separate:

- `GOOGLE_DIRECT_GROUNDING_MODEL` — direct answer model, default `gemini-3.6-flash`.
- `GOOGLE_GROUNDING_MODEL` — lower-cost retrieval/compatibility model, default `gemini-3.5-flash-lite`.

API keys are not browser-exposed, committed to the repository, or passed as public Worker variables.
