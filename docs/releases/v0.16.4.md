# v0.16.4 — Erma Flow

**07 Aug 2026 · MAJOR UPDATE · PRE-RELEASE**

Erma Flow turns the workspace from a static collection of chat, artifacts, and preview panels into a connected work system. The release introduces a site-wide motion language, controlled streaming tasks, real Agent Run history, and one-action delivery of completed results into Artifact Studio.

## Motion System

- Added shared duration, easing, distance, and interaction tokens.
- Added route entry, section reveal, workspace transition, tab, drawer, sheet, chat message, composer, status, artifact, and Flow animations.
- Added mobile-specific motion with reduced travel and faster timings.
- Added complete `prefers-reduced-motion` handling.
- Added an IntersectionObserver orchestrator for existing and dynamically mounted site sections.

## Erma Flow

- Added a dedicated workspace for complex controlled tasks.
- Uses the existing `/api/demo` streaming contract.
- Shows preparation, context/tools, result generation, and finalization stages.
- Supports Stop and preserves partial output.
- Stores a bounded local run history.
- Shows request/model metadata when available.
- Never exposes hidden model reasoning.

## Agent Runs

- Replaced the static preview timeline with real locally stored Flow runs.
- Added run selection, stage history, status, timestamps, results, and artifact links.
- Added direct navigation back to Erma Flow.

## Artifact delivery

- Flow results can be saved into Artifact Studio in one action.
- Material type is inferred as document, plan, table, code, or JSON.
- Existing artifact storage and version schemas remain compatible.

## Mobile interface

- Added direct Erma Flow access to the chat drawer.
- Improved drawer hierarchy, composer focus motion, chat message entry, overlays, sheets, status feedback, and workspace navigation.
- Added safe mobile animation timings without disabling the motion system on phones.

## Compatibility

- Existing conversations, projects, drafts, response versions, and artifacts are preserved.
- Public `/api/demo` JSON and SSE contracts are unchanged.
- Flow history uses the new local key `tklabs.erma-flow.runs.v1`.

## Known limitations

- Editing an older prompt still moves it into the composer instead of rebuilding the branch from that point.
- Flow uses the same current demo quota and access limits as the main chat.
- Flow history, artifacts, and conversations remain local to the current device.
