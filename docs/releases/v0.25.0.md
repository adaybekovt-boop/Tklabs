# v0.25.0 — Erma Evigilata

**Date:** 2026-08-13
**Channel:** Preview / Beta
**D1 migration:** None

## Summary

v0.25.0 is a mobile and desktop UI hardening pass across the chat workspace, developed as two parallel workstreams (mobile, desktop) against a shared baseline and merged into one branch. It fixes real layout, navigation, and accessibility bugs found by running the app in a real browser at the required breakpoints rather than by inspection alone. It does not change model providers, pricing, quotas, or any server-side API contract.

## Mobile changes

- `components/legal/TermsGate.tsx`: on a tall consent document, the panel could grow taller than the viewport and require scrolling the whole dialog — with no visible cue — to reach the Accept button, which sat off-screen by as much as ~170px on a 412×915 or 393×852 phone. The panel is now a flex column capped to the viewport height; the terms text scrolls in its own region while the header, checkbox, and Accept button stay fixed and always in view. Desktop layout is unchanged.
- `app/mobile-workspace.css`: the mobile Chat/Tasks/Files switcher had sub-44px tap targets (2.4rem / 38.4px in portrait, 2.1rem / 33.6px in landscape), below the project's own 44px minimum for action-critical controls. Raised to 2.75rem (44px) in both orientations.
- `app/mobile-workspace.css`: the first-time "requests are sent to an external AI provider" disclosure banner was a bottom-anchored overlay positioned only relative to the dock, with no awareness of the composer above it. On shorter phones (tested at 360×780) it rendered directly on top of the composer, fully covering the textarea, attachment button, and Send button before the banner could be dismissed. Re-anchored below the chat header instead, where it can only ever cover empty transcript space.
- Added `e2e/mobile-viewport-sweep.spec.mjs`: explicit no-horizontal-overflow checks at 320/360/390/414/430/768px portrait and three landscape sizes, a 44px tap-target sweep, a long Markdown/KaTeX/table/code-block answer overflow check, and a short-viewport (keyboard-covered height) composer-visibility check.

## Desktop changes

- History selection is now driven by the scalar `session` query value instead of a mutable search-params object, and `useChatRequest.replaceMessages()` aborts any in-flight request and resets request metadata before swapping the visible transcript — a late SSE event from a previously open chat can no longer write into the newly selected one.
- `ConversationArchive` now invokes selection directly on an ordinary click while keeping its `Link` fallback, modifier-click/new-tab behavior, and URL state intact.
- The unused `HistoryDropdown` component was removed; the persistent desktop history rail is the single history surface, now visible starting at the `md` (768px) breakpoint.
- The attachment and model popovers measure trigger and viewport geometry, bound their own width/height, flip placement when they would overflow, and track `visualViewport` resize/scroll.
- `Runs` now selects a dedicated panel and is a real, independently selectable tab — previously the tab bar kept `Flow` visually marked as selected while `Runs` content was showing.
- Model-picker keyboard handling (`Escape`, arrows, Home/End, Enter, Space) is scoped to the combobox trigger instead of a document-level listener that could capture keys away from the prompt textarea.

## Shared / infrastructure

- `@playwright/test` is now a real `devDependency` (the config referenced it without it being installed) with Chromium and WebKit browsers, used as the primary tool for both workstreams' browser verification.
- Two pre-existing e2e locator bugs were independently found and fixed by both workstreams during the same session, then reconciled during the merge rather than picked arbitrarily: an unscoped text locator that became ambiguous once the history sidebar started showing the same text as a session title, and an `[aria-expanded]` selector that could match the model-picker trigger instead of the attachment button.

## Known issues

- Real field measurements for LCP/CLS/TBT/INP on an emulated mobile profile (Slow 4G + 4x CPU throttling) were started but not completed for this release; a Playwright + `PerformanceObserver` harness exists but needs a follow-up session to finish.
- `app/page.tsx` and `app/patch-notes/page.tsx` still render separate mobile (`lg:hidden`) and desktop (`hidden lg:block`) markup branches simultaneously rather than one responsive tree; consolidation was deliberately deferred pending the Core Web Vitals measurement above, to size the actual cost before refactoring.
- `components/site/PublicBrandingGuard.tsx` and `components/site/MotionOrchestrator.tsx` batch their `MutationObserver` work per animation frame (already correct) but still observe the whole `document`/`body` rather than a scoped container.
