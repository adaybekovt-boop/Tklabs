# v0.24.0 — Erma Grounded Search & Kazakhstan Intelligence

Release date: 2026-08-09

## What changed

Erma now has a dedicated factual-grounding path for exact, current, ambiguous, historical, legal, statistical, and Kazakhstan-specific questions. The goal is to prevent confident answers when the requested fact was not actually resolved or verified.

### Exactness Router

- Added the `fact_lookup` intelligence route.
- High-risk exact questions automatically require web evidence and citations.
- Factual-risk routing promotes grounded questions to Erma Core or stronger instead of treating every short prompt as a Lite task.
- Normal conversation, creative work, and simple static questions remain lightweight and do not automatically search the web.

### Google-first web grounding

- Preferred provider: Gemini Interactions API with the built-in `google_search` tool.
- Optional legacy fallback for existing Google Programmable Search customers.
- Brave Search remains a bounded fallback when configured.
- Search results are deduplicated and ranked before entering the model evidence context.
- NVIDIA remains Erma's answer/synthesis layer; the web provider supplies external evidence rather than becoming a user-selectable model.

### Kazakhstan entity intelligence

- Russian, Kazakh, and English aliases can be resolved as the same Kazakhstan entity.
- Initial explicit entity families include Senior Zhuz / Старший жуз / Ұлы жүз, Middle Zhuz / Средний жуз / Орта жүз, and Junior Zhuz / Младший жуз / Кіші жүз.
- Kazakhstan searches can expand across RU/KZ/EN query variants.
- Topic-specific authority ranking prefers the appropriate official Kazakhstan sources, including Adilet, the Bureau of National Statistics, National Bank, Akorda, gov.kz, and e-history.kz.

### Evidence-bound answers

- Exact factual routes must search before answering.
- The planner is instructed to open at least one relevant source and to prefer two independent sources for ambiguous, historical, legal, statistical, or authority-sensitive claims when budgets allow.
- Verification records distinguish searched results from opened sources.
- Missing evidence produces an `unverified`/`partial` state and the final-answer policy explicitly forbids filling the gap with a guess.

### Better web reader

- Keeps existing public-URL/SSRF protections.
- Extracts bounded readable content from `main`, `article`, or `body`.
- Captures page title, meta description, and publication date when available.
- Removes scripts, styles, navigation, forms, headers/footers, and other common page noise.

### Search privacy

- Search queries are derived separately from the full conversation.
- Email addresses, phone-like values, URLs, known secret/token prefixes, and long token-like values are stripped before an external search request.
- Search-provider content and opened pages remain explicitly untrusted data and cannot become system instructions.
- Product Facts now disclose the web-grounding data route.

### Compatibility with the previous Erma build

- The ten dynamic Erma personality/mood modes introduced immediately before this release are preserved.
- A factual-accuracy section was added above those modes rather than replacing their behavior.

## Configuration

Preferred server-only configuration:

- `GOOGLE_GEMINI_API_KEY` (or `GEMINI_API_KEY`)
- optional `GOOGLE_GROUNDING_MODEL` (defaults to `gemini-3.5-flash-lite`)

Fallback configuration:

- legacy Google Programmable Search: `GOOGLE_SEARCH_API_KEY` + `GOOGLE_SEARCH_CX`
- Brave Search: `BRAVE_SEARCH_API_KEY`

No browser-exposed search key is introduced.

## QA

`tests/v0.24-grounded-search.test.mjs` covers:

- Senior Zhuz exact-fact routing;
- Kazakhstan factual-risk detection;
- private-data minimization before search;
- RU/KZ alias expansion;
- official Kazakhstan source authority ranking;
- Core-or-stronger routing for grounded facts;
- fail-closed verification;
- Google-first gateway/source-reader contracts;
- preservation of the previous ten-mode Erma personality layer.

## Migration

- No D1 migration.
- No client-side storage migration.
- A Google search API key is required for the preferred Google path; without it Erma can use configured fallbacks.
- If no web-search provider is configured, exact grounded routes fail closed instead of silently pretending that external verification succeeded.
