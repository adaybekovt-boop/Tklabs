# v0.16.8 — Resilience Core

**Date:** 7 August 2026  
**Channel:** Preview / beta  
**Scope:** reliability, deployment readiness, infrastructure refresh, and engineering ownership

## Summary

Resilience Core strengthens the paths that keep TK Labs usable when a provider, page, cache entry, or deployment step fails. It also rebuilds the Developers page around explicit ownership: TK is responsible for the TK Labs backend, release quality, and reliability; THOMAS TM is responsible for product architecture and AI systems.

## Engineering ownership

- TK owns the Cloudflare Worker backend, D1 and Durable Object integration, authentication and access policies, release gates, performance, production verification, fallback behavior, and incident analysis.
- THOMAS TM owns product architecture, model and agent workflows, information architecture, interface systems, and the translation of AI capabilities into product outcomes.
- Shared layers, including AI routing and the workspace, now show both owners instead of using the generic “Developer” role.

## Reliability changes

### Runtime recovery

- Added `app/error.tsx` for route-level recovery.
- Added `app/global-error.tsx` for failures that prevent the normal application shell from starting.
- Retry actions do not clear local conversations, drafts, artifacts, Flow runs, or Workspace Vault data.

### Readiness

- Added `GET /api/ready`.
- The endpoint verifies the `DB`, `CLODEX_ACCESS`, and `HEALTH_STATUS` runtime bindings.
- It exposes the active release in the response body and `x-tklabs-release` header.
- It never returns secret values or provider credentials.

### Health cache recovery

- Health provider probes use two bounded attempts for transient network and 5xx failures.
- The Durable Object validates stored snapshots before use.
- Corrupted snapshots are removed instead of crashing the status endpoint.
- A last-known snapshot can be returned as explicitly stale for up to 15 minutes when live refresh fails.
- Optional Clodex degradation does not mark the required platform unhealthy.

## Infrastructure refresh

- GitHub Actions move from `actions/checkout@v4`, `actions/setup-node@v4`, and `actions/upload-artifact@v4` to v6 actions running on the Node 24 action runtime.
- Integration tests replace the deprecated `--experimental-loader` flag with the stable `node:module` `register()` API.
- CI artifact names include the commit SHA.
- Production deployment resolves the expected application release before deployment.
- A bounded canonical-domain smoke test validates `/api/ready`, the expected release, required bindings, and the web manifest after deployment.

## Infrastructure audit

| Area | Previous state | v0.16.8 action |
| --- | --- | --- |
| GitHub actions runtime | v4 actions generated Node runtime deprecation warnings | Updated to v6 |
| Test loader | Deprecated experimental loader flag | Uses `register()` |
| Runtime failure UI | No route or root recovery boundary | Added both levels |
| Deployment verification | Wrangler success only | Canonical-domain readiness smoke test |

| Stale health fallback | Five-minute window | Explicit bounded 15-minute last-known snapshot |
| Deployment ownership | Custom workflow and Cloudflare Git Integration can both write production | External Git Integration must be disabled after workflow validation |
| Historical root documents | Several v0.9.1 handoff files remain in the repository root | Retained as history; archive cleanup deferred to avoid mixing documentation deletion with reliability changes |

## Required operational follow-up

Cloudflare Git Integration is configured outside this repository and cannot be disabled by this patch. After the custom production workflow deploys v0.16.8 successfully and the canonical-domain smoke test passes, disable automatic Git deployment for the `tkai` Worker. `.github/workflows/deploy-cloudflare.yml` should remain the only production writer.

Keeping two deployment writers can produce two builds for one commit and makes rollback ownership unclear.

## Cache migration

The Service Worker namespace is now:

```text
tklabs-v0.16.8-static
```

Previous TK Labs static caches are removed when the new Service Worker activates. API, authentication, administration, and navigation responses remain excluded from the static cache.

## Known limitations

- Readiness confirms required bindings, not the availability of every external AI provider. Provider state remains available through `/api/status` and the Status page.
- The production smoke test stops a failed workflow but does not perform an automatic rollback.
- Disabling Cloudflare Git Integration is a manual infrastructure action outside the repository.
- Health snapshots are intentionally stale-bounded; they are not presented as live data when refresh fails.
