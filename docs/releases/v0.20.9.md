# v0.20.9 — Trust Architecture

Channel: preview  
Date: 8 August 2026

Trust Architecture completes the v0.20.0–v0.20.9 cycle by making product truth, legal consent, privacy controls, storage modes, sync cryptography, runtime policy, AI provenance, Trust UX, incident publication, and release validation part of one testable architecture.

## What changed

- Product Facts Registry documents real local/server/provider boundaries.
- Legal Center 2.0 introduces a versioned legal bundle and append-only D1 acceptance evidence.
- Privacy Control Center provides local/server export, Sync deletion, local clearing, and explicit account-data deletion.
- Local / Synced / Ephemeral storage modes avoid implying on-device inference.
- Workspace Sync crypto v2 adds HKDF-separated keys, AES-GCM AAD, keyed integrity IDs, key versions, and authenticated legacy migration.
- Unified Policy Engine drives both runtime safety and public Acceptable Use copy.
- AI response metadata carries safe provenance; model cards disclose purpose, limitations, tools, provider class, and data handling.
- Mobile/desktop Trust UX provides data-route and provider disclosures in the workspace.
- Incident history is evidence-backed and never fabricates uptime; content-free audit events are bounded to 90 days.
- CI gains legal, policy, and trust consistency gates in addition to the existing security, migration, release, test, build, and performance checks.

## Required deployment changes

Apply ordered D1 migrations `0002_legal_acceptances.sql`, `0003_workspace_crypto_v2.sql`, and `0004_audit_events.sql`. Keep the legacy Workspace Sync root until legacy rows can no longer exist; optionally configure `WORKSPACE_SYNC_SECRET_V2` for v2 key material.

For a real commercial launch, the owner must supply a reviewed legal operator identity, legal/privacy contact, and jurisdiction configuration. The application intentionally does not invent these values.

## Known preview limits

- Workspace Sync is server-side encryption at rest, not end-to-end encryption.
- A strict nonce-only script CSP remains report-only until the current Next/Vinext hydration path can be browser-validated without breaking rendering; enforced CSP still requires `unsafe-inline` for framework bootstrap scripts.
- Ephemeral mode guarantees no new chat archive writes and no Workspace Sync uploads; other local workspace surfaces retain their own explicit controls.
- The public incident registry starts empty. This means no incident entries have been published in that registry, not that uptime was 100%.
