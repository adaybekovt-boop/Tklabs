# TK LAB: разбор системы и исправления

Дата: 26 сентября 2026. База: `main`, `2bbcf1124bb5ff244758f76159c2d6b510e62966`.
Ветка: `agent/backend-system-audit-20260926`.

## Вердикт

Основу проекта стоит сохранить. Локальный архив, документы, ветвление диалогов, источники и ручная синхронизация дают понятную пользу. Но число режимов, обещаний и промежуточных политик выросло быстрее, чем согласованность продукта. Следы разных проходов разработки есть: устаревшие инструкции, противоречивый промпт, параллельные реализации потоков и тесты, закрепляющие старые ошибки.

Причину нельзя доказательно свести к тому, какая модель писала код. В репозитории нет основания распределять ошибки между «сильными» и «слабыми» моделями. Техническая причина — недостаточно единых контрактов и проверок поведения между изменениями.

Предлагаемое направление: **рабочая среда для вопросов, документов и исследования с локальным архивом, понятными источниками и явным контролем данных**. Манера Erma может отличать продукт, но не должна мешать завершать задачу, скрывать ограничения или заставлять модель хвалить себя.

## Объём проверки

На базовом коммите 470 отслеживаемых файлов. Проведена инвентаризация и проверка по границам: OAuth/Worker, AI-провайдеры и доставка, аккаунты/данные, квоты/интеграции, продуктовые обещания/архитектура. Отдельно проверены изменения auth и provider lifecycle. Это инженерный аудит и исправления, а не доказательство отсутствия любых ошибок во всех сценариях.

Дизайн сохранён. Клиентские изменения относятся к целостности текста, сохранению/удалению данных, статусу потока и устаревшим названиям моделей на главной.

## Google OAuth: установленная причина

В установленной связке `next-auth` и Vinext при заданном production `AUTH_URL` функция `reqWithEnvURL` создаёт `new NextRequest(canonicalUrl, request)`. Конструктор Vinext 0.0.50 копирует объект Request через spread и теряет унаследованные поля, включая `headers`, `method` и `body`. Callback поступает в Auth.js уже без Cookie. PKCE-проверка отклоняет вход, хотя исходная cookie правильно расшифровывается.

Ошибка воспроизведена в собранном Worker: native server action формы `/login` выдаёт PKCE-cookie, а callback возвращает `InvalidCheck`. Отдельный тест `@auth/core` при этом проходит — поэтому одной unit-проверки Auth.js было недостаточно.

HTTP-обработчики теперь передают исходный стандартный Request напрямую в официальный `@auth/core`. Серверные `auth()`/`signIn()` сохраняются. Добавлены request-time конфигурация, канонизация домена входа, доверенные forwarded headers и проверка подтверждённого Google email. Повторный Worker-прогон прошёл: форма → PKCE → callback → читаемая сессия. Результат перепроверен независимо. Google в этом тесте подменён; настоящий production login проверяется после выкладки.

## Польза человеку и противоречия продукта

Повод пользоваться есть, если человеку удобно работать с документами, возвращаться к архиву, видеть источники и сохранять результаты в одном месте. Репозиторий не доказывает, что это удобнее альтернатив: нужны завершённые задачи и реальные повторные возвращения.

1. **Собственная модель.** Erma — интерфейс, политика и маршрутизация над внешними провайдерами. Собственное обучение и превосходство нельзя заявлять без доказательств.
2. **Flow и агентность.** Flow выполняет один `/api/demo`; этапы формирует клиент, Runs хранит локальную историю. Закрытие компонента прекращает работу. Долговечной системы фоновых заданий с checkpoint/resume здесь пока нет.
3. **Лимит и работа.** Три запроса за суточное окно, затем две рекламные страницы минимум по 20 секунд за бонус создают существенное препятствие для итеративной работы. Без себестоимости нельзя честно назначить новый лимит. Сначала измерить стоимость полезного результата и долю пользователей, которым лимит мешает завершить задачу.
4. **Local-first.** Локальный архив не означает локальный inference. Ручная копия D1 не является E2EE или автоматическим backup. Эти различия должны совпадать в текстах и поведении.
5. **Рекламные бонусы.** API подтверждает прошедшее время, не подписанное событие рекламной сети. Функция выключена по умолчанию. До server-to-server подтверждения нельзя считать её доказательством просмотра или подтверждённой бизнес-моделью.

## Архитектурное направление

Сохранять модульный монолит Worker. Сильные стороны: отдельные секреты для идентификаторов, серверные права, versioned consent, ограниченные тела/контекст, reserve/commit/release, явные fallback и локальный архив.

Единый путь генерации: запрос → авторизация/согласие/квота → инструменты/источники → admission → ответ → settlement. JSON/SSE должны использовать одинаковые правила; UI не должен придумывать собственную семантику успеха.

Оставшиеся структурные ограничения:

- Scheduler ограничивает финальную генерацию; planner, council и direct grounding могут обращаться к провайдерам отдельно. Общий контроль стоимости/конкурентности пока неполный.
- У стадий отдельные timeout; единого request-wide deadline нет.
- JSON/SSE ещё дублируют бизнес-логику. Следующее выделение — общий исполнитель, выдающий события, а не новая иерархия «движков».
- Публичный и серверный каталоги возможностей дублируются. Есть неиспользуемые `chat-modes.ts`, публичный `resolveAutoErmaModelKey`, `experience-capabilities.ts`. Удаление требует проверки импортов/поведения, а не массового переименования.
- `verification.status=verified` — эвристика о наличии источников, не доказательство истинности всех утверждений.
- Consent блокирует UI, но не серверные AI API; у demo намеренно есть анонимный путь. Это требует явного решения по публичному API, а не заявления об универсальной серверной проверке согласия.
- Локальный архив/память относятся к браузеру, а не Google-аккаунту; смена аккаунта на общем устройстве не создаёт отдельное хранилище.
- Очистка audit events старше 90 дней запускается при новых записях, не по расписанию. Metadata Drizzle отражает только 0000, хотя SQL-миграции доходят до 0004: перед следующим db:generate нужна синхронизация metadata. Исторические orphan rows в production не искались и не удалялись.
- `AGENTS.md` описывает прошлую desktop-ночь, `IMPLEMENTATION_PLAN.md` смешивает старые релизы. Актуальная карта ответственности теперь в `docs/ARCHITECTURE.md`; инструкции не переписаны ради обхода разрешений.

## Предлагаемые критерии следующего выпуска

Это план измерений, а не полученные показатели:

- Настоящий Google login на каноническом домене завершается workspace-сессией.
- 15–20 собственных задач проверяют завершённый результат, корректные ссылки и честную неопределённость; для каждой фиксируется стоимость и число повторов.
- Время первого токена p50/p95 и ошибки учитываются отдельно по провайдерам; пользовательская отмена не является отказом провайдера.
- Stop/retry, потеря сети, возврат к истории и экспорт сохраняют точный текст и статус.
- Экспорт/удаление покрывают заявленные данные; конкурентное сохранение не теряет новую версию.
- Новый режим добавляется под конкретную пользовательскую задачу с проверяемым результатом.

## Валидация и внешние ограничения

Production-секреты, D1-данные и платные AI-запросы не менялись. Ветка сама по себе не обновляет рабочий сайт.

Проверки итогового состояния:

- `npm run check`: PASS — typecheck, ESLint (0 ошибок, 5 существующих предупреждений в persistence.ts), secret scan, migration/policy/legal/release checks, 22 unit и 372 integration tests, production build, built-Worker OAuth и performance budget.
- `npm audit --omit=dev --audit-level=high`: PASS, 0 известных production-уязвимостей на момент проверки.
- `wrangler deploy --dry-run` для основного Worker: PASS. Это проверка упаковки, не деплой.
- Telegram: `npm run check` (types + dry-run): PASS; 14 целевых support/Telegram регрессий PASS. Отдельная проверка в workerd: три одинаковых подписанных webhook приняты, mocked sendMessage выполнен один раз, повтор после completed receipt не отправляет ответ снова.
- Собранный основной Worker: native login action → PKCE callback → HTTP/RSC session → canonical redirect → CSRF sign-out: PASS, внешняя сеть заменена тестовыми ответами.
- Чистый клиентский JS: 1317.9 KiB при бюджете 1367.2 KiB; gzip 423.7/429.7 KiB; CSS 153.7/156.3 KiB. Бюджеты не увеличены; запас по gzip и CSS небольшой.
- `git diff --check`: PASS.

Telegram использует существующий binding BOT_STATE. Очередь ограничена 32 заданиями; по 5 попыток генерации и доставки; receipts/cache ограничены 7 днями и 1024 записями; `/reset` очищает и cache. Exactly-once не обещается: crash после принятия sendMessage Telegram, но до сохранения checkpoint может повторить один фрагмент; crash между завершением AI и атомарным сохранением может повторить запрос провайдеру.

Публичные GET-пробы tklabs.uk вернули 200 для `/login`, `/api/ready`, `/api/auth/providers`, `/api/auth/csrf`; сайт сообщил v0.25.0. Это подтверждает начало входа, не callback. Production smoke из Node в этой среде завершился по сетевому timeout, поэтому не считается пройденным.

Локальная браузерная регрессия остановилась до открытия браузера: Cloudflare Vite plugin не смог вызвать os.networkInterfaces (`uv_interface_addresses`, EPERM). Проверка включена в Browser Assurance; живой UI в этом окружении не подтверждён.
