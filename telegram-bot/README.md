# TKlab Telegram Bot

Telegram-бот для мониторинга `https://tklabs.uk`. Работает в Cloudflare Workers.

## Возможности

- проверяет сайт по расписанию Cloudflare Cron;
- сообщает об аварии после нескольких неудачных проверок и отправляет сообщение о восстановлении;
- принимает команды через Telegram webhook;
- хранит состояние мониторинга и историю диалога в Durable Object; история изолирована по пользователю и чату, изменения одного диалога выполняются последовательно;
- ограничивает доступ по Telegram ID.

После перехода на изоляцию по чату диалоги начнутся с чистой истории. Старые объекты `user:<id>` не используются: они могли содержать смесь личных и групповых сообщений, которую нельзя безопасно разделить задним числом.

## Надёжность webhook

Webhook проверяет секрет Telegram и разрешённого пользователя, ограничивает тело запроса 64 КБ и сохраняет обновление вместе с alarm в одной транзакции. HTTP 200 возвращается только после её завершения. Генерация и отправка ответа выполняются через alarm существующего `BOT_STATE`; дополнительный binding или сервис не нужен.

Входящая очередь содержит максимум 32 обновления. При заполнении или ошибке сохранения возвращается 503, чтобы Telegram повторил доставку. Повторный `update_id` не создаёт новую задачу: квитанции хранятся до 7 дней, максимум 1024 последние. После обработки исходное сообщение и исходящий текст удаляются из записи очереди. Для повторного запуска генерации после сбоя ответ и история диалога сохраняются атомарно в объекте пользователя; этот кэш также ограничен 7 днями/1024 ответами и очищается командой `/reset`.

Исходящий ответ записывается до отправки; после каждой успешно подтверждённой части сохраняется позиция. Генерация и доставка имеют отдельные бюджеты по 5 попыток с увеличением задержки. Ответ Telegram `429` учитывает `retry_after` (до 24 часов). После исчерпания попыток генерации бот ставит в исходящую очередь сообщение о временной недоступности. Исчерпание попыток доставки записывается событием `telegram_inbox_failed` в логи Worker.

Доставка Telegram не гарантирует строго «ровно один раз»: если Telegram принял часть ответа, а Worker завершился до сохранения подтверждения, при восстановлении эта часть может отправиться повторно. Telegram `sendMessage` не принимает ключ идемпотентности. Обычные повторные webhook и ошибки доставки не запускают оплаченную генерацию заново после сохранения ответа; сбой непосредственно между ответом AI-провайдера и его записью также остаётся внешней транзакционной границей.

## Команды

- `/start`, `/help` — список команд;
- `/status` — проверка главной страницы;
- `/health` — проверка основных endpoint'ов сайта;
- `/commits [N]` — последние коммиты репозитория;
- `/reset` — очистить историю диалога.

## Деплой

Деплой выполняется GitHub Actions при push в `main`.

GitHub Environment: `TELEGRAM_BOT_TOKEN`

Обязательные секреты:

- `TELEGRAM_BOT_TOKEN`;
- `TELEGRAM_ALLOWED_USER_IDS`;
- `TELEGRAM_WEBHOOK_SECRET`;
- `CLOUDFLARE_API_TOKEN`.

Дополнительные секреты:

- `REPO_GITHUB_TOKEN` — нужен для доступа к приватному репозиторию;
- `CLODEX_API_KEY` — нужен для AI-ответов.

После деплоя workflow автоматически загружает секреты Worker, регистрирует webhook Telegram и проверяет его состояние.

## Локальный запуск

```bash
npm ci
npm run check
npm run dev
```

Для локального запуска секреты можно указать в `.dev.vars`. Файл `.dev.vars` не добавляется в Git.
